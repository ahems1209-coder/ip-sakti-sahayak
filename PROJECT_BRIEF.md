# Project Brief: IP-SAKTI Sahayak
**SIH 2026 Problem Statement:** PS2026045 / SIH26045  
**Product Category:** Multilingual, Evidence-Grounded AI Decision-Support System for Intellectual Property, Traditional Knowledge & ABS Regulatory Compliance.

---

## 1. Executive Summary

**IP-SAKTI Sahayak** is an institutional-grade, evidence-grounded decision-support platform designed to solve key challenges in Intellectual Property (IP), Traditional Knowledge (TK), Access and Benefit Sharing (ABS), and regulatory compliance for Ayurveda and Indian Systems of Medicine (ASU&H). 

Unlike generic generative AI chatbots that risk legal hallucinations or fabricating citations, IP-SAKTI Sahayak operates on a **strict evidence-grounded workflow**. Every substantive legal, regulatory, or traditional knowledge claim generated by the system must be directly mapped to verified authoritative source documents (e.g., Indian Patent Act, Biological Diversity Act, TKDL guidelines, Drugs & Cosmetics Act, AYUSH notifications, WIPO treaties). If insufficient evidence exists in the verified knowledge base, the system strictly **abstains** from generating speculative answers or fake legal citations.

---

## 2. Core Workflow & Architectural Principles

### 2.1 Core Workflow
1. **User Query / Formulation Submission** (Text, Ingredients, Regulatory Query)
2. **Language Detection & Translation Layer** (Normalizes non-English query to English, preserving query intent)
3. **Query & Jurisdiction Classification** (Maps query to domain: Patent, TK, ABS, ASU&H Regulation, GI, Trademark)
4. **Authoritative Evidence Retrieval** (Hybrid BM25 keyword + pgvector dense semantic retrieval over authoritative corpus)
5. **Evidence Validation Layer** (Strict verification of chunk relevance, applicability, and completeness)
6. **Grounded Answer Generation** (Extracts factual synthesis exclusively from validated chunks)
7. **Source Citation & Claim Verification** (Maps each synthesized claim to exact `chunk_id`, section number, page, and official source URL)
8. **Multilingual Response Synthesis** (Translates verified answer back to regional language while preserving exact original source citations)

### 2.2 Core Mandates
- **Zero Hallucination Tolerance:** No synthetic legal conclusions, fake government partnerships, manufactured URLs, or unsubstantiated statistics.
- **Provider Abstraction:** Decoupled interfaces for LLM providers, retrieval engines, vector stores, and translation engines (e.g., Bhashini, Google Translate, Mock).
- **Institutional UX:** Analytical dashboard, formal evidence breakdown, and clear legal disclaimer markers. Not a conversational chat widget.

## 3. Scope & Knowledge Domains

### 3.1 Phase 1 MVP Scope (India-First Focus)
- **Patents:** Indian Patent Act 1970, Patent Rules, Section 3(p) / 3(e) exclusions regarding traditional knowledge and ASU&H formulations.
- **Ayurveda / ASU&H Regulation:** Drugs & Cosmetics Act 1940 (Chapter IVA), ASU&H Rules, Pharmacopoeial Standards (API/GPI), Ministry of Ayush notifications.
- **Traditional Knowledge:** TKDL framework guidelines, classical Ayurvedic text references (Charaka Samhita, Sushruta Samhita, etc. indexed structure).
- **Biodiversity & ABS:** Biological Diversity Act 2002, Biological Diversity Rules 2004, National Biodiversity Authority (NBA) guidelines on benefit sharing for commercial utilization of bio-resources.
- **Geographical Indications:** Geographical Indications of Goods (Registration and Protection) Act 1999 & registered GI registry references.
- **Trademarks:** Trade Marks Act 1999 pertaining to traditional names and generic Ayurvedic terms.

### 3.2 Phase 2 Scope (International Domain Expansion)
- WIPO Treaties & Guidelines (Gratis/TK conventions)
- Patent Cooperation Treaty (PCT) framework
- TRIPS Agreement (WTO)
- Convention on Biological Diversity (CBD) & Nagoya Protocol on ABS

## 4. Key Application Modules

1. **Dashboard:** High-level overview of query analytics, active IP compliance checks, recent formulation evaluations, and system audit logs.
2. **AI Assistant:** Institutional query interface returning structured legal/regulatory assessments with confidence metrics, jurisdiction flags, and interactive source citations.
3. **Formulation Assessment Module:** Automated evaluation tool for Ayurvedic & polyherbal formulations. Users input product name, active botanical ingredients, intended therapeutic use, classical reference status, and target jurisdiction to receive an IP/ABS risk matrix.
4. **Source Explorer:** Searchable, verified digital library of authoritative legal acts, guidelines, gazette notifications, and section-by-section breakdowns with hash-verified provenance.

## 5. Technical Requirements & Output Standards

### 5.1 Structured Output Format
All AI responses must strictly conform to a validated JSON schema prior to UI rendering:
```json
{
  "answer": "Formulations containing Neem (Azadirachta indica) utilizing classical processes documented in Ayurveda Pharmacopoeia are non-patentable under Section 3(p) of the Indian Patent Act, 1970. However, commercial utilization of bio-resources requires prior approval from the National Biodiversity Authority under Section 3 of the Biological Diversity Act, 2002.",
  "claims": [
    {
      "text": "Classical processes documented in Ayurveda Pharmacopoeia are non-patentable under Section 3(p).",
      "source_chunks": ["IND-PAT-1970-SEC3P-C01"]
    },
    {
      "text": "Commercial utilization of bio-resources requires prior NBA approval under Section 3.",
      "source_chunks": ["IND-BDA-2002-SEC03-C02"]
    }
  ],
  "jurisdiction": "India",
  "confidence": "evidence_supported",
  "needs_review": true
}
```

### 5.2 Backend Output Validation Rule
If a generated claim lacks a valid, verified `source_chunk` ID or fails evidence validation checks, the backend **must reject the claim** or transition the response status to `"insufficient_evidence"`.

## 6. Resilience & Security Features

- **Demo Mode Architecture:** Built-in offline demo engine backed by verified, pre-indexed cached query-response pairs from authoritative sources to ensure 100% reliable live demonstrations during SIH evaluations without external API dependency failures.
- **Confidential Mode:** Privacy-preserving execution mode wherein formulation inputs, ingredient combinations, and proprietary queries are processed purely in ephemeral memory and explicitly excluded from persistent database storage or log traces.
